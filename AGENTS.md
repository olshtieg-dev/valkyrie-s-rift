# AGENTS.md

Instructions for AI coding agents working in this repository. Humans: see [README.md](README.md).

## 🔒 Project vision: read it, never edit it

[`VISION.md`](VISION.md) defines what this game is. **Read it before designing or building anything.** Every feature, level, and mechanic must serve it.

`VISION.md` is **immutable for agents**. Never edit, rename, move, or delete it, and don't route around it by restating a different vision elsewhere. Only the project lead changes it, by hand. If a request conflicts with the vision, stop and ask the user.

## ⚠️ You are not alone in this working tree

**Several agents and humans edit this project at the same time, in the same checkout.** The Godot editor may also be open and saving files. Assume any file can change between the moment you read it and the moment you write it.

Rules:

1. **Read right before you write.** Re-read a file immediately before editing it. Never edit from a copy you read earlier in the session.
2. **Make small, targeted edits.** Change only the lines you need. Do not rewrite or reformat whole files. A full-file write erases whatever someone else just added.
3. **Never discard work you didn't make.** Do not run `git checkout -- <file>`, `git restore`, `git reset`, `git stash`, `git clean`, or delete/overwrite files you didn't create. Uncommitted changes in `git status` are usually someone else's live work, not leftovers.
4. **Stage and commit only your own files, by explicit path.** Never `git add -A` / `git add .` / `git commit -a`. Don't commit at all unless the user asks.
5. **If you collide, stop.** If a file you're editing changed unexpectedly, or your edit fails because the text moved, re-read it and merge your change into the new version. If the other change conflicts with yours, stop and ask the user. Don't overwrite it.
6. **Stay in scope and announce it.** Sign in under [Active workers](#active-workers) before editing. Don't do drive-by refactors, renames, or file moves. Those break other agents' in-flight edits.
7. **No branch switching or history rewriting** (`git switch`, `rebase`, `commit --amend`, `push --force`). Everyone shares this checkout's branch.

### Godot-specific collision hazards

- `.tscn`, `.tres` and `project.godot` are **rewritten wholesale by the Godot editor on save**. If the editor has the scene open, a hand edit can be silently overwritten, and an unsaved editor change can overwrite yours. Prefer changing `.gd` scripts. When you must edit a scene or resource as text, keep it minimal and tell the user, so they can reload it in the editor without saving over it.
- Don't hand-renumber `ext_resource`/`sub_resource` ids or change `uid://` values. Other files reference them.
- `.gd.uid` and `.import` files are generated by Godot. Commit them alongside their source file, but don't edit them by hand.
- `.godot/` is a local cache (git-ignored). Never edit it. Deleting it forces a slow full reimport for whoever is running the editor.

## Environment

- **Engine:** Godot **4.6-stable**, standard build (GDScript only, no C#/.NET). The exact version is in [`.godot-version`](.godot-version).
- **Install:** `sh tools/setup.sh` (Linux/macOS) or `tools\setup.ps1` (Windows) puts `godot` on PATH. If `godot` isn't found, run the setup script; don't hardcode an executable path.
- **Cross-platform team:** collaborators use Linux and Windows. Never write absolute or OS-specific paths into the project. Use `res://` / `uid://` paths in Godot files and relative paths in tooling. Line endings are LF (enforced by `.gitattributes`).
- **Renderer:** Forward+. **Physics:** Jolt (3D setting; the game is 2D). Textures use nearest filtering (pixel art).

## Project layout

| Path | Contents |
|---|---|
| `project.godot` | Project settings, input map, autoloads, physics layer names |
| `game.tscn` | Main scene |
| `scenes/` | Reusable scenes (player, enemies, platforms, weapons, `ui/`) |

| `tilesets/` | Shared `TileSet` resources |
| `data/` | Game data resources. `data/weapons/*.tres` are `WeaponData` (swing scene, damage, element, and the movement/flutter each sword gives her) |
| `assets/` | Sprites, sounds, music, fonts. See `assets/LICENSE & CREDITS.txt` before adding or redistributing |
| `tools/` | Dev-environment setup scripts |

**Autoload:** `GameManager` (`scripts/gamemanager.gd`) holds score and the player state carried across levels.

**Input actions:** `move_left`, `move_right`, `move_up`, `move_down`, `jump`, `attack`, `switch_weapon`, `interact`. Use these names. Don't read raw keys.

**2D physics layers:** 1 `world`, 2 `player`, 3 `enemy`, 5 `hazard`, 6 `one_way`.

## Conventions

- GDScript is indented with **tabs**. Use static typing where practical (`var x: int`, `-> void`) and `##` doc comments for exported or shared members, matching the existing scripts.
- Prefer signals for cross-node communication, and the input actions above for controls.

## Assets: harvest freely

Sourcing free pixel art, sprites, tilesets, sounds, music, and fonts from the web is **encouraged** (see `VISION.md`). Prefer a good existing asset over a placeholder or a hand-drawn one. How to do it:

1. **Check the license before downloading.** Allowed: CC0 / public domain, CC-BY, CC-BY-SA, or a license explicitly allowing free use in commercial games. Not allowed: NC (non-commercial) or ND (no-derivatives) licenses, "personal use only", no stated license, or anything ripped from an existing commercial game. If it's unclear, skip it.
2. **Good sources:** [OpenGameArt](https://opengameart.org), [itch.io free game assets](https://itch.io/game-assets/free) (read each pack's license), [Kenney](https://kenney.nl/assets) (CC0), [Freesound](https://freesound.org) (filter by CC0 / CC-BY).
3. **Fit the style.** The game is pixel art with nearest filtering on a **16×16 base grid**: tiles and standard creatures are built on it. Sizes vary beyond that: bosses can be much larger, and decorative, non-interactive life (insects, critters) can be smaller or larger. Keep pixel density consistent: don't scale sprites up or down to fit (no blurry or mixed-size pixels), and avoid clashing palettes.
4. **Place files** under `assets/sprites/`, `assets/sounds/`, `assets/music/`, or `assets/fonts/`, in a subfolder named after the pack or author (e.g. `assets/sprites/kenney_pixel_platformer/`). Keep any license file that ships with the pack.
5. **Credit it in the same change.** Append an entry to `assets/LICENSE & CREDITS.txt` with the asset name, author, source URL, and license. An asset without a credits entry must not be committed.
6. **Let Godot import it** (`godot --headless --import`) so the `.import` files are generated, and commit those with the asset.

Downloaded archives are untrusted. Unpack them into a scratch folder and copy only the media files you need (images, audio, fonts) into `assets/`. Never run scripts or executables from a pack.

## Verifying changes

There is no test suite yet. Check that the project loads and scripts parse without errors:

```sh
godot --headless --import                     # (re)import assets; also catches broken resources
godot --headless --quit-after 120 2>&1 | grep -iE "error|warn"   # run ~2s, show script errors
```

Both commands only write to the `.godot/` cache (and new `.import` files for new assets), so they are safe to run while others work. Don't launch the editor (`godot -e`). The user runs that.
